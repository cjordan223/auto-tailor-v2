# Tex-Tailor Implementation Guide
# Internal documentation for developers and customization

## 🌐 WEB INTERFACE OVERVIEW

The web interface provides a modern UI for the Python CLI backend:

### Architecture
```
Vue.js Frontend (port 3000) → Express.js API (port 3001) → Python CLI → AI Providers
```

### Key Files
- `frontend/src/` - Vue.js frontend application
- `frontend/server/` - Express.js API server
- `frontend/package.json` - Dependencies and scripts

### Quick Start
```bash
cd frontend
npm install
npm run dev  # Starts both frontend and backend
```

### Server Configuration
**File:** `frontend/server/index.js`

### API Key Processing
**File:** `frontend/server/routes/process.js`
- Accepts API keys from frontend requests as JSON
- Merges with environment variables (frontend takes precedence)
- Passes merged environment to Python CLI subprocess
- Secure handling: keys only transmitted during processing, not stored on server

### API Key Validation
**File:** `frontend/server/routes/validate.js`
- Real API validation endpoints for all providers
- Makes actual API calls to verify key validity
- Handles rate limits, timeouts, and connection errors
- Secure validation: keys not logged or stored

### Real-time Output Streaming
**File:** `frontend/server/routes/process.js`
- **Output Parsing Engine**: `parseOutputAndUpdateStatus()` function analyzes CLI stdout/stderr
- **Progress Mapping**: Maps CLI messages to meaningful progress percentages and descriptions
- **Error Categorization**: Intelligent detection of API auth, timeout, rate limit, and general errors
- **Provider Detection**: Automatically identifies which AI provider is being used
- **Status Enhancement**: Rich status updates with step, detail, provider, and error information

## WHERE TO TUNE THE MODEL & ADD PERSONALITY

### 🧠 MAIN PROMPT SYSTEM (PRIMARY LOCATION)
**File:** `tex_tailor/proposer.py`
**Lines:** 12-94 (SYSTEM_PROMPT variable)

This is the PRIMARY location where the AI's personality and behavior is controlled.

Key sections to modify:
- Line 12: Main system prompt starts here
- Lines 18-25: Constraint descriptions (how strict/flexible the AI should be)
- Lines 84-93: Examples section (teaches AI through examples)

To make the AI more conversational/creative:
- Reduce emphasis on "deterministic" behavior
- Add personality descriptors like "helpful", "creative", "conversational"
- Modify constraint language to be less restrictive

### 🎛️ MODEL PARAMETERS (SECONDARY TUNING)
**File:** `tex_tailor/proposer.py` 
**Lines:** 174-178 (Ollama), 222-227 (Gemini), 283-285 (OpenAI)

Temperature settings control creativity:
- temperature: 0 = very deterministic, 1 = very creative
- top_k: Lower = more focused, higher = more diverse
- Currently set to maximum determinism (temp=0, top_k=1)

### 📋 VALIDATION CONSTRAINTS
**File:** `tex_tailor/schema.py`
**Lines:** 68-75 (FORBIDDEN_LATEX_PATTERNS)

Controls what the AI is allowed to output. Currently very permissive.

### 🔧 PROVIDER CONFIGURATION  
**File:** `tex_tailor/config.py`
Default models and settings for each provider.

## ARCHITECTURE OVERVIEW

### 📁 FILE STRUCTURE & RESPONSIBILITIES

```
tex_tailor/
├── cli.py           # 🚪 Entry point - command line interface
├── proposer.py      # 🧠 AI interaction - PROMPT & MODEL TUNING HERE
├── schema.py        # ✅ Validation rules - what AI can/cannot do
├── config.py        # ⚙️  Provider settings & default models
├── extractor.py     # 📤 Extracts text from LaTeX templates
├── patcher.py       # 📝 Applies AI edits back to LaTeX files
├── differ.py        # 🔄 Shows what changed between versions
├── markers.py       # 🏷️  Handles LLM chunk markers in LaTeX
└── logger.py        # 📊 Logging utilities
```

### 🔄 EXECUTION FLOW
1. **CLI** (`cli.py`) → parses commands, orchestrates workflow
2. **Extractor** (`extractor.py`) → reads LaTeX, extracts editable content
3. **Proposer** (`proposer.py`) → sends to AI, gets back edits JSON
4. **Schema** (`schema.py`) → validates AI output meets constraints  
5. **Patcher** (`patcher.py`) → applies edits back to LaTeX files
6. **Differ** (`differ.py`) → shows what changed

## PROVIDER NOTES

**Gemini:** Best balance of speed, quality, and cost
**OpenAI:** Highest quality, most expensive  
**Ollama:** Free local models, requires more setup

Default priority: Gemini → OpenAI → Ollama

## DEBUGGING TIPS

1. **AI not following instructions?** → Check `proposer.py` SYSTEM_PROMPT
2. **Validation errors?** → Check `schema.py` constraint functions
3. **LaTeX not applying?** → Check `patcher.py` marker matching
4. **Provider issues?** → Check `config.py` and environment variables

## ENVIRONMENT VARIABLES

Required for providers:
- `GEMINI_API_KEY` - Google Gemini API key
- `OPENAI_API_KEY` - OpenAI API key  
- `OLLAMA_BASE_URL` - Ollama server URL (default: http://127.0.0.1:11434)

Model selection:
- `GEMINI_MODEL` - Override default Gemini model
- `OPENAI_MODEL` - Override default OpenAI model
- `OLLAMA_MODEL` - Override default Ollama model
