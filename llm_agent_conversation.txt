# LLM Agent Conversation - Rate Limiting Improvements & Gemini 1.0 Pro Addition

## Issue Description
User reported frequent 429 rate limit errors during testing with Gemini 1.5 Flash (15 RPM limit). Analysis showed:

**Current API Call Pattern**:
- Single API call per workflow to `propose_edits()` function
- Retry logic can make up to 3 total calls (1 initial + 2 retries)
- Retries happened immediately, potentially hitting rate limits

**Root Causes**:
1. **Immediate Retries**: No backoff between failed attempts
2. **Low Rate Limits**: Gemini 1.5 Flash limited to 15 RPM
3. **Burst Testing**: Rapid successive requests during development
4. **No Frontend Protection**: No mechanism to prevent rapid button clicks

## Solution Implemented

### 1. Added Gemini 1.0 Pro Model Option
**Frontend** (`ProviderSelector.vue`):
```javascript
models: [
  { id: 'gemini-1.5-flash', name: 'Gemini 1.5 Flash', description: 'Fast and efficient (Recommended)' },
  { id: 'gemini-1.5-pro', name: 'Gemini 1.5 Pro', description: 'Higher quality, slower' },
  { id: 'gemini-1.0-pro', name: 'Gemini 1.0 Pro', description: 'High rate limits (60 RPM), good for testing' }
]
```

**Benefits**:
- **60 RPM vs 15 RPM**: 4x higher rate limit for testing
- **Same API Key**: Uses existing `GEMINI_API_KEY`
- **Mature Model**: Stable performance for development

### 2. Implemented Exponential Backoff for Retries
**Backend** (`proposer.py`):
```python
if attempt < max_retries:
    print(f"Validation failed (attempt {attempt + 1}): {violations}")
    # Exponential backoff: wait 2^attempt seconds (2, 4, 8...)
    backoff_time = 2 ** attempt
    print(f"Retrying in {backoff_time} seconds to avoid rate limits...")
    time.sleep(backoff_time)
    continue
```

**Backoff Schedule**:
- **Attempt 1**: Immediate
- **Attempt 2**: Wait 2 seconds  
- **Attempt 3**: Wait 4 seconds
- **Total Max Wait**: 6 seconds across all retries

### 3. Added Frontend Rate Limiting Protection
**API Layer** (`useAPI.js`):
```javascript
// Rate limiting state
const lastRequestTime = new Map()
const MIN_REQUEST_INTERVAL = 5000 // 5 seconds between requests

const checkRateLimit = (endpoint) => {
  const now = Date.now()
  const lastTime = lastRequestTime.get(endpoint) || 0
  const timeSinceLastRequest = now - lastTime
  
  if (timeSinceLastRequest < MIN_REQUEST_INTERVAL) {
    const waitTime = MIN_REQUEST_INTERVAL - timeSinceLastRequest
    throw new Error(`Rate limit: Please wait ${Math.ceil(waitTime / 1000)} seconds before making another request`)
  }
  
  lastRequestTime.set(endpoint, now)
}
```

**Enhanced Error Handling**:
- **429 Status Detection**: Specific handling for rate limit responses
- **User-Friendly Messages**: Clear countdown timers
- **UI State Management**: Returns to step 2 on rate limit errors

### 4. Improved Error User Experience
**Frontend** (`Home.vue`):
